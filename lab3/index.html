The Problem: Your Wearable is Lying to You (a little)

Your fitness band has 3 sensors inside it trying to guess your heart rate: an optical LED sensor, a wrist-motion sensor, and a small ECG strip. Each one is a little bit wrong on its own. The band mixes all three together to get the final BPM number you see on screen.

But nobody has told the band how much to trust each sensor. That's today's job.

Socho: teen dost tumhe teen alag guess dete hain ki abhi tumhara heart rate kya hai. Sabki baat kitni maanni hai — yeh weight tumhe nikaalna hai.

If True_BPM = w1×Sensor1 + w2×Sensor2 + w3×Sensor3, you now have 3 equations, 3 unknowns (w1, w2, w3). Grab a pen. Try to solve it by elimination.

Question to keep in your head: if this took you several minutes for 3 unknowns... how would you solve this for 3,000 wearables, each with slightly different sensors, before lunch?

MEET THE TOOL

The Backslash Operator: \

MATLAB has one operator that solves Ax = b for x — instantly, and safely, no matter how many unknowns.

Jitne bhi equations ho, MATLAB ek line mein solve kar deta hai — x = A \ b

Tiny example (unrelated to our wearable — just for practice)

A = [2 1; 1 3];
b = [8; 13];
x = A \ b;
disp(x)

This solves: 2x1 + x2 = 8 and x1 + 3x2 = 13. Try typing this into MATLAB right now before moving on.

Quick mental check: what do you think x will be? Type your guess, then run it in MATLAB to check.
x1 = 2.2, x2 = 3.6

Note: A\b does NOT literally invert A. Internally it factorizes A (breaks it into simpler pieces — this is the "matrix factorization" idea) and solves directly. This is faster and more reliable than inv(A)*b. Avoid inv() for solving equations.

EXERCISE 4 — Stretch

What If a Sensor Gets Stuck?

Task: Imagine Unit B's Sensor 2 and Sensor 3 readings in Sessions 2 and 3 came out almost identical (a stuck sensor). Change two rows of A_B so they're nearly equal, then run: 
A_B_bad = [70 71 69; 95 97 96.9; 150 152 151.9];
w_B_bad = A_B_bad \ b_B;
rcond(A_B_bad)
Before you run it: write one sentence predicting what will happen and why.
MATLAB will likely print a warning that the matrix is close to singular, and rcond will be a very small number (close to 0). This means the weights w_B_bad cannot be trusted — the sensors were giving almost the same information, so there isn't enough independent data to separate their individual weights.
