Speed-from-distance is differentiation. Distance-from-speed is integration. Both done on sampled numbers, not a clean formula — that's what today's lab is about.

Numerical differentiation

We'll use a clean curve first — y = x² — so every number is easy to check by hand. The same three methods apply to messy real data later.

f'(x) ≈ (f(x+h) − f(x)) / h

Forward difference — looks ahead only.

f'(x) ≈ (f(x) − f(x−h)) / h

Backward difference — looks behind only.

f'(x) ≈ (f(x+h) − f(x−h)) / 2h

Central difference — looks both ways, usually most accurate.

The MATLAB one-liners

% central difference across a whole array — this is what gradient() does
x = [1 2 3];
f = x.^2;
central = gradient(f, x);   % built-in, central by default
fwdbwd  = diff(f) ./ diff(x); % diff() gives forward differences

Numerical integration

Same curve, y = x², area under it from x = 0 to 4. Exact answer (calculus): 21.33. Change the number of strips and watch the estimate close in.

T = h · [ (f₀+fₙ)/2 + Σ fᵢ ]

Trapezoidal rule — straight-line strips.

S = (h/3) · [f₀+4f₁+2f₂+…+fₙ]

Simpson's rule — curved (parabola) strips, needs an even number of intervals.

Strips:

The MATLAB one-liner

x = 0:1:4;
f = x.^2;
area = trapz(x, f);   % built-in trapezoidal integration

MATLAB has no plain simpson() — for real functions (not just sampled data) it uses adaptive quadrature instead: integral(@(x) x.^2, 0, 4).

Common slips

⚠️Making h too small doesn't make things "more accurate forever" — past a point, MATLAB's own rounding starts adding noise back in.
⚠️Simpson's rule needs an even number of intervals — odd breaks the paired-parabola pattern it relies on.
⚠️Mixing units (minutes vs seconds) silently before integrating gives a confidently wrong number — check units first.

Problem 1 · Integration

Billing an EV charging session

A charging station logs current draw every 5 minutes during a session. Total charge delivered (in Amp-minutes) decides the bill.

t (min)05101520
Current (A)24753

Write MATLAB code using trapz to find the total charge. Then answer: would Simpson's rule work directly on this data as-is? Why or why not? (C6 — justify your choice, don't just compute.)

t = [0 5 10 15 20];
I = [2 4 7 5 3];
charge = trapz(t, I);   % = 92.5 A·min

Simpson's rule needs an even number of intervals — here there are 4 (even), so it's actually usable; but the data is unevenly interesting (a peak at t=10), so trapz on real sampled readings is the safer default. Simpson helps more when you're integrating a known smooth function, not noisy real sensor data.

Problem 2 · Differentiation

Is the packing line slowing down?

A conveyor's cumulative unit count is logged every minute. Maintenance wants the packing rate at t = 2 min, and whether it's trending down.

t (min)01234
Units packed050105150180

Find the rate at t = 2 using the central difference. Then answer: comparing forward and backward differences around t = 2, is the line speeding up or slowing down — and which method would you trust for a maintenance alert, and why?

t = [0 1 2 3 4];
u = [0 50 105 150 180];
rate = (u(4)-u(2)) / (t(4)-t(2));   % central diff = 50 units/min

Backward rate (t=1→2) is 55 units/min; forward rate (t=2→3) is 45 units/min. The rate is falling — the line is slowing down. Central (50) is the best single estimate for "right now"; the forward/backward gap is itself the useful maintenance signal.
