Before the real data

Warm-Up: Core MATLAB Commands

Four quick drills covering the interface essentials you'll use every session from here on.

Drill 1 · Arithmetic + ans

Type 12 + 8 and press Enter (no semicolon). Then type ans.

MATLAB prints ans = 20. Whenever you don't store a result in a named variable, MATLAB stashes it in ans automatically — and you can reuse it in the next line.

Drill 2 · The Colon Operator

Type 1:5, then 1:2:10.

1:5 → 1 2 3 4 5. 1:2:10 → 1 3 5 7 9 (the middle number is the step size). You'll use this for time axes and loops in later sessions.

Drill 3 · disp() vs Plain Echo

Type x = 42 (no semicolon), then disp(x).

x = 42 without ; prints x = 42. disp(x) prints just 42 — cleaner, no variable-name clutter. Use fprintf when you need a full formatted sentence.

Drill 4 · clc, clear, whos

Type whos. Then clc. Then whos again.

clc clears the screen only — whos still lists your variables untouched. clear (try separately) actually deletes them. Mixing these two up is the #1 reason people "lose" their data mid-session.

Common beginner mistakes
  • HR and hr are different variables — MATLAB is case-sensitive.
  • Spaces or commas both work inside [ ] — [1 2 3] and [1,2,3] are identical.
  • = assigns a value; == checks equality. Mixing them up is the most common early bug.

Checkpoint 1 — Basic Statistics

Your task

Fill in the blanks to find Aarav's average, peak, lowest reading, and reading count.

% aarav is already in your workspace from the Dataset tab
avg_hr  = ____(aarav);   % average
peak_hr = ____(aarav);   % highest reading
rest_hr = ____(aarav);   % lowest reading
n       = ____(aarav);   % how many readings

avg_hr = mean(aarav); → 106.47   peak_hr = max(aarav); → 131

rest_hr = min(aarav); → 72   n = length(aarav); → 15

sum() just adds everything up; mean() does that too, then divides by the count — that division is the only difference between them.

Checkpoint 2 — Cardio Zone Count

Here's all 15 of Aarav's readings, checked against 120 bpm one at a time:

Count the green chips above — that's exactly what sum(aarav > 120) does in one line instead of you counting by hand.

Your task

Complete the line that counts cardio-zone minutes, then print it as a sentence.

cardio_mins = sum(aarav ____ 120);
fprintf('You spent %d minutes above 120 bpm\n', ____)

compare, then sum — that's the whole trick

cardio_mins = sum(aarav > 120);   fprintf('You spent %d minutes above 120 bpm\n', cardio_mins);

Result: 5.

Why does sum() work on a True/False list?

MATLAB treats true as the number 1 and false as 0 internally. So aarav > 120 silently becomes a list of 1s and 0s, and sum() on that list is just counting how many 1s (trues) there were.

Checkpoint 3 — Compare a Second Runner

Your task

Using meera, find her average and peak. State whether her peak was higher or lower than Aarav's (131 bpm).

avg_meera = mean(meera); → 96.33   peak_meera = max(meera); → 119

Meera's peak (119 bpm) is lower than Aarav's (131 bpm) — Aarav pushed harder at some point in his jog.

Bonus (optional) — a sneak peek of Session 5: plot(1:15, aarav, '-o', 1:15, meera, '-o'); draws both jogs on one graph. Try it — you'll get the formal version of this in the Visualization session.

Checkpoint 4 — Predict the Break

Your task

Imagine 7 runners' data from the same day. Before revealing anything, write down your own prediction first.

  • Could you keep storing each one as aarav, meera, runner3 ... runner7?
  • What's the first thing that gets annoying at 7 runners? At 30?
  • Could you plot all 7 runners together in one line of code, the way things stand today?

It works for a while but stops scaling fast: you can't loop over separately-named variables automatically, can't plot all 7 in one line, and can't ask "what did everyone's heart rate look like at minute 5?" without opening each variable one by one. At 30 runners it's unworkable.

Loose end for next week: stack all runners as rows inside one matrix, so the whole group lives in a single variable.
