FAQ — Do I have to use the Editor, or can I keep typing into the Command Window?

The Command Window is fine for one-off checks, but it forgets everything the moment you close MATLAB unless you explicitly save your workspace. A script file is a plain text recipe you can re-run, edit, and hand to someone else. From today onward, every exercise assumes you're working in a script.

Why does my Workspace panel matter more than I think?

It's the fastest way to catch bugs. If you expect a 1×15 vector and the Workspace shows 15×1, you've transposed something by accident — you'll spot that instantly here, long before it causes a confusing error three lines later.

Before the canteen data

Warm-Up: Operators, Types & Precision

Four drills — try each directly in the Command Window before reading the reveal.

Drill 1 · Operator Precedence

Type 2 + 3 * 4. Then type (2 + 3) * 4.

2 + 3 * 4 → 14 — multiplication happens before addition, same BODMAS rule as on paper. Parentheses force the order you want: (2+3)*4 → 20. ^ (power) binds even tighter than * and /.

Drill 2 · class()

Type class(5), class('hi'), class("hi"), and class(5 > 3).

class(5) → double. class('hi') → char (single quotes = a character array). class("hi") → string (double quotes = a string object — newer, and usually easier to work with). class(5>3) → logical. MATLAB decides the type automatically — you never declare it up front.

Drill 3 · format short vs long

Type pi. Then format long, then pi again. Then format short to go back.

format short (the default) shows 3.1416. format long shows 3.141592653589793. MATLAB was never rounding the actual stored value — only what got displayed. format stays changed for the rest of the session until you switch it back.

Drill 4 · Comments

In the Editor, type a line starting with %, then a normal code line below it, and run the script.

The % line is skipped entirely — comments exist purely for you and your reader, MATLAB ignores them. For a whole block, wrap it between %{ and %} on their own lines.

Common beginner mistakes
  • A variable name can't start with a digit — 2ndPrice is invalid, price2 is fine.
  • Don't name a variable i or j if you'll need the imaginary unit later — you'll silently overwrite it.
  • Forgetting to save the .m file before running it — MATLAB runs the last saved version, not what's currently on screen.

Optional — extra practice

Lab Tasks

Optional, and separate from the four core Exercises. Use the canteen data below (type it into a script first):

items  = {'Samosa','Tea','Sandwich','Maggi','Cold Coffee','Burger'};
prices = [15 10 40 35 45 60];
qty    = [22 40 15 18 25 10];

items is a cell array — a container that can hold text of different lengths side by side, something a normal vector can't do.

Task 1

Find the total number of items sold today, across all six items.

sum(qty) → 130

Task 2

Find today's total revenue (price × quantity, summed across all items).

sum(prices .* qty) → 4685 — the .* multiplies each price by its matching quantity, item by item, before sum adds them all up.

Task 3

Check whether every item priced above ₹30 also sold at least 10 units (a sanity check that nothing expensive is going unsold).

all(qty(prices > 30) >= 10) → 1 (true) — prices > 30 picks out which items to check, and all() confirms every one of them clears the bar.

Task 4

Find the typical spread in prices across the menu (how much prices vary, not just their average).

std(prices) → ≈ 17.94 — the standard deviation. A small value would mean the menu is priced narrowly; this one tells you there's a real spread from ₹10 tea to ₹60 burgers.

Checkpoint 1 — A Script That Asks a Question

Your task

Fill in the blanks so the script asks the user how many samosas (₹15 each) they want, then prints the cost.

% prices(1) is the samosa price from the canteen data above
n    = ____('How many samosas? ');   % reads a number typed by the user
cost = n * prices(1);
fprintf('That will be Rs. %d\n', ____);

n = input('How many samosas? ');   fprintf('That will be Rs. %d\n', cost);

input() pauses the script and waits — whatever the person types becomes the value of n. This is the first time your script reacts to someone other than you.

Checkpoint 2 — Naming the Best Seller

You already know max() returns the largest value. It can also tell you where that value sits — its position — if you ask for a second output.

Your task

Fill in the blanks to find which item sold the most, and print its name in a sentence.

[bestQty, bestIdx] = ____(qty);     % bestIdx = position of the largest value
bestItem = items{____};             % curly braces pull text out of a cell array
fprintf('Today\'s best seller is %s, sold %d times\n', bestItem, bestQty);

curly braces unwrap a cell — square brackets would keep it wrapped

[bestQty, bestIdx] = max(qty);   bestItem = items{bestIdx};

Result: Today's best seller is Tea, sold 40 times. %s in fprintf inserts text; %d inserts a whole number.

Checkpoint 3 — A Sanity-Check Script

Your task

Before trusting today's numbers, check two things: (a) that no item's quantity is negative or zero, and (b) whether at least one item is priced at ₹50 or more.

all(qty > 0) → 1 (true) — every quantity is a sane, positive number.

any(prices >= 50) → 1 (true) — the burger at ₹60 clears that bar.

all() demands every element pass; any() only needs one. That's the whole difference between them.

Checkpoint 4 — Predict the Break

Your task

Imagine tracking the canteen for a full Monday–Saturday week, not just one day. Before revealing anything, write down your own prediction.

  • Could you keep today's qty vector and just add a second vector qtyTue, qtyWed...?
  • What breaks first — finding the busiest single day, or finding the best-selling item across the whole week?
  • What single MATLAB object could hold six days × six items in one place?

Six separate vectors work for a day or two, but "which day sold the most Maggi?" already needs you to open all six and compare by eye. Ask for a whole week's total per item, or per day, and there's no clean one-line answer with separate vectors.

Loose end for next week: stack all six days as rows inside one matrix — one variable, six days × six items — and let row/column sums answer both questions in a single line.
