Why today matters

You already know how to build and add matrices — now make them work for you

You've built matrices with zeros, ones, and eye, and you know how to add, multiply, and transpose them. What you haven't done yet is reach inside one to pull out exactly the piece you need, glue two matrices together, or use one to solve for an unknown price. That's today.

Concatenation

Stacking a new row or bolting on a new column with [A; B] and [A B].

Inversion & Solving

inv() and the backslash \ — solving a system of equations in one line.

^

Power: Matrix vs. Element

A^2 (matrix multiplication) is not the same animal as A.^2 (square every entry).

FAQ — Didn't I already learn addition, subtraction, multiplication, and transpose?

Yes — that covered building matrices and combining two matrices that are already the right shape. Today is about reshaping and reaching into a matrix, and about the one arithmetic operation that wasn't covered yet: inversion, and what it's actually for (solving equations, not just "the opposite of multiply").

Before the exercises

Warm-Up: Reaching Into a Matrix

Four drills using the sales matrix from the Dataset tab.

Drill 1 · Single Cell & end

Type sales(1,1), then sales(end,end).

sales(1,1) → 22 (Monday, Samosa). sales(end,end) → 18 — end always means "the last index in this dimension," so you never have to hard-code the size.

Drill 2 · Whole Row / Column

Type sales(3,:), then sales(:,2).

sales(3,:) → all of Wednesday's sales: 19 38 18 22 27 8. sales(:,2) → all five days of Tea sales as a column: 40 35 38 42 45. The colon alone means "everything along this dimension."

Drill 3 · size() and numel()

Type size(sales), then numel(sales).

size(sales) → 5 6 (5 rows, 6 columns). numel(sales) → 30, the total count of cells — the same as multiplying the two size numbers together.

Drill 4 · Matrix Power vs Element Power

Make a small square matrix P = [1 2; 3 4]. Type P^2, then P.^2.

P^2 → [7 10; 15 22] — that's P * P, real matrix multiplication. P.^2 → [1 4; 9 16] — every entry individually squared, no multiplication between rows and columns at all. Same symbol family, completely different operations.

Common beginner mistakes
  • A(2,3) is row 2, column 3 — always row first, column second.
  • A^2 only works if A is square; A.^2 works on any size.
  • Concatenating [A; B] needs the same number of columns; [A B] needs the same number of rows — mismatches throw a dimension error.

Lab Tasks

Optional, standalone one-liners using sum(...,dim) and reshape — functions not formally taught today but guessable from context. Try these using the sales matrix.

Task 1

Find the total units sold per item across the whole week (one number per column).

sum(sales, 1) → 125 200 91 95 144 62 — summing "down" each column, dimension 1.

Task 2

Find the busiest single day (highest total items sold that day).

[dayTotal, dayIdx] = max(sum(sales, 2)); → Friday, row 5, total 168. sum(sales,2) sums "across" each row, dimension 2.

Task 3

Reshape the 5×6 matrix into a single column of 30 values (imagine feeding it into a simple list-based report).

reshape(sales, 30, 1) — same 30 numbers, rearranged column by column into one long column. The total count of elements must stay the same before and after.

Task 4

Pull out just Wednesday–Friday's Tea and Maggi numbers (a 3×2 slice from the middle of the matrix).

sales(3:5, [2 4]) → rows 3 through 5, only columns 2 and 4. A colon range picks consecutive rows/columns; a bracketed list like [2 4] picks specific, non-consecutive ones.

Checkpoint 1 — Saturday Joins the Matrix

Your task

Fill in the blanks to add Saturday's row [27 33 19 21 26 15] to the bottom of sales, and a new "Cold Drink" column [8;10;6;9;12] to the right of the original five weekday rows (before adding Saturday).

% adding a new column to the original 5-row matrix
coldDrink = [8; 10; 6; 9; 12];
salesPlus = [sales ____];

% adding Saturday as a new row (7 columns now, matching salesPlus)
saturday  = [27 33 19 21 26 15 11];
weekSales = [salesPlus ____ saturday];

salesPlus = [sales coldDrink]; — square brackets placed side-by-side glue columns together (horzcat), as long as both have the same number of rows.

weekSales = [salesPlus; saturday]; — a semicolon between them stacks rows (vertcat), as long as both have the same number of columns.

Checkpoint 2 — Solving for Unknown Prices

The canteen lost its price list. A student remembers: "3 samosas + 2 teas cost ₹65" and another remembers "2 samosas + 4 teas cost ₹80." That's two equations, two unknowns — exactly what a matrix inverse solves.

Your task

Fill in the blanks to set up and solve the system for the samosa price x and tea price y.

A = [3 2; 2 4];     % coefficients of x and y in each equation
b = [65; 80];       % the right-hand totals

prices = ____(A) * b;     % or equivalently: A \ b
fprintf('Samosa = Rs.%.0f, Tea = Rs.%.0f\n', prices(1), prices(2));

A \ b avoids computing the inverse explicitly — faster & more accurate for bigger systems

prices = inv(A) * b; — or the preferred form, prices = A \ b;

Result: Samosa = Rs.15, Tea = Rs.10 — matching the actual prices from Practical 1B.

inv(A) only exists when A is square and its determinant is non-zero (you met det() last session — a zero determinant is exactly when a system like this has no single solution).

Checkpoint 3 — Power, the Right Way

Your task

Take a 2×2 slice of the sales matrix — Monday & Tuesday, Samosa & Tea columns: M = sales(1:2, 1:2). Compute both M^2 and M.^2, and explain in one sentence why only one of them makes sense as "this week's sales, squared."

M = sales(1:2,1:2) → [22 40; 28 35]

M.^2 → [484 1600; 784 1225] — each sales count individually squared. This is meaningful: e.g. "squared Monday-samosa count."

M^2 → [2352 2280; 1596 2345] — real matrix multiplication of M by itself. The numbers no longer correspond to anything about sales at all; matrix power only makes physical sense when the matrix represents a transformation being repeated, not a table of counts.

Checkpoint 4 — Predict the Break

Your task

Imagine the canteen wants to find the single busiest item-day combination (e.g. "Friday's Tea") automatically, not by eyeballing the matrix. Before revealing anything, write your own prediction.

  • Would max(sales) alone answer this, or does it only look one dimension at a time?
  • Could find() or a nested search help pin down the exact row and column?
  • What if the canteen wanted to repeat this analysis automatically every single day — what MATLAB construct would you need that you haven't used yet?

max(sales) only finds the largest value in each column, giving six separate answers — not the one overall busiest cell. Getting a single global answer needs max(sales(:)), which flattens the matrix into one long list first — a preview of reshaping ideas from today's Lab Tasks.

Loose end for next session: repeating a check like this automatically, day after day without retyping it, is exactly what loops and conditionals (for, if) are for — that's where the course goes next.

Recap & Viva Prep

IndexingA(row,col) — row always comes first.
Colon & end: means "everything here." end means "the last one."
Concatenation[A B] glues columns. [A; B] stacks rows.
Solving systemsA \ b (or inv(A)*b) solves Ax = b directly.
Power vs .^A^2 multiplies matrices. A.^2 squares each entry.
size vs numelsize gives rows & cols. numel gives the total count.
