Stack It Into a Grid

Last week you left a loose end: separate variables stop working once the data grows. Today you merge 3 days of heart rate, steps and calories into one matrix — and then add, scale, multiply and invert it.

⏱ 60 min core + 20 min quiz 📋 Prerequisite: Practical 1 🎯 CO1 · CO2 · Matrix operations 🟢 Track: Fitness Wearable

Step 1 · 5 min · hands off the keyboard

Nine variables for one week is nine too many

Aarav's wearable now logs three things every day, not one: average heart rate, step count, and calories burned. The coach wants three days of it. For Aarav and Meera.

With last week's tools, that means typing this:

% Monday
aarav_mon_hr = 106;  aarav_mon_steps = 8200;  aarav_mon_cal = 310;
% Tuesday
aarav_tue_hr =  98;  aarav_tue_steps = 6400;  aarav_tue_cal = 245;
% Wednesday ... and now do all of that again for Meera

That's 18 variables before you've computed anything. Now answer these, out loud, without touching MATLAB:

  • What were Aarav's total steps across the three days?
  • Which day did he burn the most calories?
  • What's the combined step count for both runners, day by day?
  • Thursday's data arrives. How many lines do you edit?

every answer needs you to hunt through 18 names

Step 2 · 3 min

And the quick fix doesn't save you

"I'll just do it in Excel." Fair — for three days you can. Here's where that breaks:

1

It doesn't remember how

Drag a formula down and you've got answers, not a method. Next week's data means doing the whole thing again by hand.

2

It can't be looped

You cannot write "do this for every runner" over eighteen separately-named variables. There's nothing to loop over.

3

It stops at three

Practical 1's data was one runner. Today it's two. An EV battery pack has 8 cells. A drone has 4 IMUs. The approach has to survive that.

The promise from last week

At the end of Practical 1 you predicted this exact wall. The fix you guessed was right: put the whole thing in one grid. That grid is called a matrix, and today you learn the four things you can do to it.

M

Merge & address

One name holds the whole table. A(2,3) reaches any single number inside it.

±

Add, subtract, scale

Combine two runners' logs, or find the gap between them, in one character.

×

Multiply

Turn a table of raw counts into one score per day using a rulebook.

÷

Invert

Run the maths backwards to recover a rulebook nobody gave you.

Type both into MATLAB now — every exercise below reuses these exact names:

aarav = [106  8200  310
          98  6400  245
         112  9750  388];

meera = [ 96  9100  355
          92  7300  280
         101 10400  402];

3 rows = 3 days · 3 columns = 3 metrics

How does MATLAB know where the rows end?

Inside [ ], a space or comma moves you along the current row. A semicolon or a new line starts the next row. So [1 2 3] is one row of three, and [1;2;3] is three rows of one. They are different shapes and MATLAB treats them differently.

Lining the numbers up in columns like the code above is purely for your eyes — MATLAB ignores the extra spaces. Do it anyway; you will be reading this file again in the viva.

Wait — the columns have different units. Is that allowed?

Yes, and it's normal. A matrix is just a grid of numbers; it doesn't know or care that column 1 is bpm and column 2 is steps. Each column is one consistent quantity, which is what matters.

The catch: because the units differ across a row, adding along a row is meaningless. 106 + 8200 + 310 is not a number that describes Monday. You'll see MATLAB compute exactly that nonsense in Exercise 2 — happily and without a single warning.

🔢 Try it yourself — live matrix playground

Pick an operation. You'll see the result grid, its shape, and whether the answer actually means anything. This is exactly what MATLAB does when you type the same thing.

Step 3 · 7 min · syntax on tiny examples

Meet the Tool: four drills

Small numbers, so you can check every answer in your head. Do these before touching the real data.

Drill 1 · A vector is already a matrix

Type size(aarav). Then bring back last week's vector: hr = [72 75 88 102 110]; and type size(hr).

size(aarav) → 3 3  ·  size(hr) → 1 5

Nothing new happened last week — hr was always a matrix with one row. size always answers rows first, then columns. Every list you made in Practical 1 was a 1 × n matrix.

Drill 2 · Reaching inside

Type aarav(2,3), then aarav(:,2), then aarav(3,:), then aarav(end,end).

aarav(2,3) → 245 — row 2, column 3. Tuesday's calories.

aarav(:,2) → 8200; 6400; 9750 — the colon means "all of them", so this is the whole Steps column.

aarav(3,:) → 112 9750 388 — all of Wednesday.

aarav(end,end) → 388 — end means "last", so this is the bottom-right corner.

Row first, column second, counting from 1. aarav(3,2) and aarav(2,3) are different numbers. Get this backwards and you'll report Tuesday's calories as Wednesday's step count.

Drill 3 · Add, subtract, scale

Build two tiny grids and try all three:

P = [1 2; 3 4];   Q = [10 20; 30 40];

Type P + Q, then Q - P, then 10 * P, then P + [1 2 3].

P + Q → 11 22 / 33 44 — matching positions added.

Q - P → 9 18 / 27 36 — matching positions subtracted.

10 * P → 10 20 / 30 40 — a single number multiplies every element. Always allowed, any shape.

P + [1 2 3] → error. P is 2×2, that's 1×3. To add or subtract two grids, the shapes must match exactly.

Drill 4 · The dot changes everything

With the same P and Q, type P .* Q and then P * Q. They give different answers.

P .* Q → 10 40 / 90 160 — the dot means "position by position". 1×10, 2×20, 3×30, 4×40. Shapes must match.

P * Q → 70 100 / 150 220 — no dot means real matrix multiplication: walk along a row of P, down a column of Q, multiply the pairs, add them up. Top-left is 1×10 + 2×30 = 70.

The shape rule for *: write the two shapes side by side. (2×2)·(2×2). If the two inner numbers match, it's allowed, and the answer takes the two outer numbers. Here that's 2×2.

That rule is the single most useful thing in today's session. You'll use it in Exercise 3 to turn a table of counts into one score per day.

Common beginner mistakes
  • aarav(0,1) is an error. MATLAB counts from 1, not 0 — different from C and Java.
  • aarav(3,4) is an error too: there is no 4th column. Use size when you're unsure.
  • Building a column with commas: [1,2,3] is a row. Columns need semicolons: [1;2;3].
  • * and .* both often run without complaint, and give different answers. That's worse than an error, because nothing tells you.

Lab Tasks

Checkpoint 1 — Merge and Inspect

Scaffolding: fill in the blanks

Before you can operate on a matrix you have to be able to describe it and reach into it. Four blanks.

Your task

Report the shape of Aarav's log, how many numbers it holds, Tuesday's calorie burn, and the whole Steps column.

% aarav is already in your workspace from the Dataset tab
shape    = ____(aarav);      % rows and columns
how_many = ____(aarav);      % total numbers inside
tue_cal  = aarav(__,__);     % Tuesday's calories
all_steps = aarav(__,__);   % every day's step count

shape = size(aarav); → 3 3  ·  how_many = numel(aarav); → 9

tue_cal = aarav(2,3); → 245 — Tuesday is row 2, calories is column 3.

all_steps = aarav(:,2); → 8200; 6400; 9750 — the colon takes every row.

Compare that last line to Practical 1, where reaching one reading meant aarav(4). A matrix needs two coordinates instead of one. That's the only real change.

Checkpoint 2 — Team Totals and the Gap

Scaffolding: partial code, you finish the lines

The coach wants two things: the pair's combined effort, and how far apart the two runners are.

Your task
  1. Build team — both runners' logs combined.
  2. Build gap — Meera minus Aarav. Look at the signs and write one comment line saying what a negative number means here.
  3. Add up each column of Aarav's log. Then add up each row. One of those two answers is nonsense — say which, and why.
team = aarav __ meera;
gap  = meera __ aarav;

down_columns  = sum(aarav);      % what does each number mean?
across_rows   = sum(aarav, __);   % and each of these?

MATLAB will not warn you about the nonsense one

team = aarav + meera;

   202   17300     665
   190   13700     525
   213   20150     790

gap = meera - aarav;

   -10     900      45
    -6     900      35
   -11     650      14

Column 1 is negative every day: Meera's heart rate was lower than Aarav's on all three days, while her steps and calories were higher. She did more work at a calmer heart rate.

sum(aarav) → 316   24350   943 — sums go down the columns by default. So: three days of HR added together, total steps, total calories. Steps and calories are useful; 316 "total heart rate" is meaningless — for that column you want mean(aarav(:,1)) = 105.33.

sum(aarav,2) → 8616   6743   10250 — the 2 means "go across the rows instead". This is the nonsense one: 106 + 8200 + 310 adds a heart rate to a step count to a calorie count. MATLAB computes it instantly and says nothing. Legal is not the same as sensible.

Why does team = aarav + meera work at all?

Because both are 3×3. Addition and subtraction work position by position, so they need identical shapes — same rows, same columns. Try aarav + aarav(:,1) and you'll see MATLAB do something surprising rather than refuse; that's a convenience feature called implicit expansion, and it's a common source of silent bugs. For now: match your shapes deliberately.

Checkpoint 3 — One Score Per Day

Scaffolding: hints only, no skeleton

The college fitness challenge has a rulebook:

  • Heart rate isn't scored at all — 0 points per bpm.
  • 1 point per 1,000 steps → 0.001 points per step.
  • 2 points per 100 calories → 0.02 points per calorie.

You need one Fit Points number per day, per runner. Notice what that actually asks for: walk along a day's row, multiply each metric by its rate, add the three results. That is matrix multiplication.

Your task
  1. Build the rulebook as a column called rates.
  2. Before running anything, write in a comment: what shape will aarav * rates be, and why? Use the inner-number rule.
  3. Compute daily Fit Points for both runners, then each runner's three-day total.
  4. Try rates * aarav. Record what happens and explain it in one line.
  5. Try aarav * meera. It runs. Say in one line why the result is garbage.

Shape check first — which of these are even allowed?

Green = allowed and sensible. Orange = MATLAB allows it but the answer means nothing. Red = error.

Hint — why rates must be a column

aarav is 3×3. Write the shapes side by side and check the inner pair: (3×3)·(3×1) — inner numbers both 3, so it's allowed, and the answer is 3×1. Three rows, one column: one score per day. Exactly what you wanted.

If you build rates with commas you get a 1×3 row, and (3×3)·(1×3) has inner numbers 3 and 1 — error. Semicolons make columns.

rates = [0; 0.001; 0.02];   % per bpm; per step; per calorie

points_a = aarav * rates;   % (3x3)*(3x1) -> 3x1, one score per day
points_m = meera * rates;

total_a = sum(points_a);
total_m = sum(points_m);

Aarav: 14.40, 11.30, 17.51 → total 43.21

Meera: 16.20, 12.90, 18.44 → total 47.54

Check Monday for Aarav by hand: 0×106 + 0.001×8200 + 0.02×310 = 0 + 8.2 + 6.2 = 14.4. That single number is one row of the matrix meeting one column of the rulebook. Nine such calculations happen in one keystroke.

Meera wins the challenge despite a lower heart rate every day — the rulebook rewards steps and calories, not effort.

rates * aarav → error. (3×1)·(3×3): inner numbers 1 and 3 don't match. Order matters — matrix multiplication is not like ordinary multiplication where 3×4 = 4×3.

aarav * meera → runs fine, gives a 3×3. Both are 3×3 so the inner numbers match. But the result mixes Aarav's heart rate with Meera's step counts by row-and-column position. It's arithmetically valid and physically meaningless — nobody warns you.

Checkpoint 4 — Recover the Missing Rulebook

Scaffolding: none — you're on your own

The challenge results are up on the noticeboard: three students, three final Fit Points scores. But the page with the rulebook has been torn off. Nobody knows how many points a thousand steps was worth.

You do have each student's logged quantities:

StudentSteps (thousands)Calories (hundreds)Active (10-min blocks)Published points
Ravi42620
Priya35223
Kabir61419

In Exercise 3 you had the rulebook and computed the scores. This is the same equation read backwards: you have the quantities and the scores, and the rulebook is the unknown.

Your task
  1. Build the 3×3 quantity matrix Q (one student per row) and the scores column t.
  2. Check whether a unique answer even exists — use det and rank — before you try to find it.
  3. Solve it two ways: with inv, and with the backslash \.
  4. Verify. Multiply Q by your answer and check you get t back.
  5. Print the three point-rates as three readable sentences with fprintf.
Hint — setting the equation up

You are looking for a column of three unknown rates, call it r. Each student's score is their row of quantities times that rate column. All three at once: Q * r = t, with Q being 3×3 and t being 3×1.

To get r out, you need to undo the multiplication by Q. Multiplying by the inverse of Q does that, the same way multiplying by ⅓ undoes multiplying by 3. In MATLAB that's inv(Q)*t — or better, Q\t.

If your t prints as one row, you built it with commas. Rebuild it with semicolons.

Q = [4 2 6
     3 5 2
     6 1 4];
t = [20; 23; 19];

det(Q)          % -90  : not zero, so an inverse exists
rank(Q)         %   3  : full rank, so the answer is unique

r_inv = inv(Q)*t
r_bs  = Q\t     % same answer, and the better habit

Q*r_bs          % 20 23 19 — matches t, so we're right

Both methods give r = 2, 3, 1. The missing rulebook was: 2 points per 1,000 steps, 3 points per 100 calories, 1 point per 10 active minutes.

Hand-check Ravi: 4×2 + 2×3 + 6×1 = 8 + 6 + 6 = 20. ✓

Why check det first? If det(Q) had been 0, there would be no inverse and no unique answer — and you'd want to know that before wasting time. rank tells you how badly it failed: a rank of 3 on a 3×3 means all three rows carry genuinely new information.

Why prefer Q\t? Backslash solves the equation directly instead of building a whole inverse matrix and then throwing it away. It's faster and more accurate. Reach for inv only when you actually want the inverse matrix itself as an object.

Loose end for next week: Aarav's wearable reports raw sensor counts, not true bpm — and the calibration constants that convert one to the other are unknown. That's the same trick you just did, on a system that doesn't have a neat square matrix. Next session: solving linear equations properly, and finding out when inverting is the wrong move.

Step 5 · 3 min · the trade-off

Watch Out: when the grid is the wrong tool

A matrix is powerful because it treats everything as an anonymous grid of numbers. That's also exactly what makes it dangerous.

Right tool

Same kind of thing, rectangular

3 days × 3 metrics. 8 battery cells × 2 readings. 4 IMUs × 3 axes. Every row the same length, every column one consistent quantity.

Wrong tool

Ragged data

Monday you logged 15 readings, Tuesday only 9. A matrix must be rectangular, so you'd have to pad with fakes. Later sessions give you tables and cell arrays for this.

Wrong tool

Text mixed with numbers

Runner names, day labels, device IDs. A numeric matrix can't hold them. Keep labels in a separate variable — that's why we kept day names out of the grid.

Right tool

Same operation, every element

Convert all steps to kilometres, add two weeks together, score a whole table against a rulebook. One line, no loop.

Try breaking the inverse on purpose (30 seconds)

Suppose Priya's log had been exactly double Ravi's — same activities, twice as much of everything:

Qbad = [4 2 6; 8 4 12; 6 1 4];

Run det(Qbad) → 0, and rank(Qbad) → 2. Then inv(Qbad) warns that the matrix is singular to working precision and hands you Inf.

Why: Priya's row tells you nothing Ravi's row didn't already say. Two real facts, three unknowns — the rulebook can't be pinned down. That's a data problem, not a coding one, and no amount of retyping will fix it.

One more oddity you'll hit: −0.0000

Type Q*inv(Q). You should get the identity matrix — 1s down the diagonal, 0s elsewhere. You'll mostly get that, plus the odd -0.0000, and isequal(Q*inv(Q), eye(3)) will say false.

Nothing is broken. Computers store decimals approximately, so the answer lands about 0.0000000000000001 away from exact. When you need to check "is this the identity?", compare with a tolerance instead: norm(Q*inv(Q) - eye(3)) < 1e-10.
